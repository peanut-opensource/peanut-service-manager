# 花生服务管理器：首版确认需求

- 中文名：花生服务管理器；英文名：Peanut Service Manager。
- Codex 项目显示名：服务管理台。
- 确认日期：2026-10-17。
- 状态：产品方案已确认，本次仅落档，不开始应用、MCP、安装器或发布工作流开发。
- 本文件为首版产品需求事实源；[README](../README.md) 为摘要入口。

## 1. 定位与平台

面向 macOS 的本机服务管理应用，集中配置、启停和观察服务，并向 AI 客户端提供同等能力。

- Swift 原生方案，界面使用 SwiftUI，系统交互按需使用 AppKit。
- 最低支持 macOS 12，兼容 Intel（x86_64）和 Apple Silicon（arm64）。实现须兼顾最低系统版本，不能因采用新系统 API 而缺失旧系统能力。
- 首版管理本机进程，不管理远程主机进程。登记资源连接地址不等于获得远程主机控制能力。
- 以后支持其他操作系统时按功能复刻，首版不引入跨平台界面框架。
- 公开开源，MIT 许可证。

## 2. 对象与组织

### 项目、环境和服务

- 基础归属为「项目 → 环境 → 服务」，各对象支持添加、修改、移除。
- 环境支持开发、生产和自定义名称，名称不局限于开发场景。
- 每个服务归属于明确的项目和环境；同一套代码可以通过不同服务配置用于不同环境。
- 例如 Peanut Admin 可以配置后端、租户管理后台、平台管理后台、PC 前端、H5 前端、对外产品文档站和内部开发者文档站。

### 分组与选择

- 环境内支持添加、修改和移除自定义服务分组，用于选择部分服务组合。
- 同一服务允许加入多个分组，引用原服务，不复制配置或运行实例。
- 支持单选、多选，以及按分组、环境、项目选择服务。
- 多个分组包含同一服务时，批量操作按稳定 ID 去重，只操作一次。
- 移除分组或成员只改变组合关系，不删除或隐式停止服务。
- 例如管理后台组与用户端组可以共享同一个后端服务。

### 身份与目标

- 项目、环境、分组、服务、资源分别使用稳定 ID。
- 服务显示完整「项目 / 环境 / 服务」路径，分组不替代服务原归属。
- MCP 修改、启停和绑定操作须明确目标，不凭可能重名的名称直接执行。
- 多个匹配时返回候选并要求明确目标，不自动选第一个。

## 3. 服务配置与运行

### 配置

每个服务包含名称、说明、工作目录、启动命令或脚本、可选环境变量、可选本地运行时版本，以及「随管理器启动」开关。

### 执行与环境

- 设置工作目录，使用所选运行时和进程环境执行命令，效果对应用户在本机命令行进入目录后执行命令。
- 后台执行不必打开可见终端窗口，不为每个服务创建虚拟机或容器。
- 跟踪实际服务进程，获取标准输出、标准错误；不能把短暂启动命令退出一概视为服务停止。
- 仅管理本应用启动或通过保留归属记录准确重新识别的进程，不能仅按名称或端口结束其他进程。
- 服务环境变量以可选变量名 / 值表配置，支持代理等用途，只影响该服务及子进程，不改变整机配置。
- 项目已有 `.env`、框架配置和启动参数仍由项目程序或启动工具处理，不要求搬到管理器。
- 支持通过启动参数或环境变量选择同一套程序的不同环境。
- 配置优先级、`.env` 读取与代理变量是否生效遵循目标程序规则，不统一假定所有程序支持。
- 资源绑定不自动改写项目配置文件或注入数据库连接信息。

### 操作与状态

- 单个及批量启动、停止、重启，自动更新状态并显示失败原因。
- 已运行服务跳过重复启动；单个操作失败不阻止批次其他目标执行。
- 停止先请求正常退出；超时提示用户是否强制停止，不直接强制结束。
- 重启确认原实例停止后才启动；取消强制停止或停止失败时不并行启动新实例。
- 删除运行中的服务前提示并处理停止，不能删记录后遗留无法管理的进程。级联移除项目、环境时同样处理其运行服务。
- 服务正常退出、异常退出或被停止，不导致管理器退出。
- 第一版不管理项目 / 服务启动依赖，不推导启动顺序，不自动崩溃重启或反复重试。

## 4. 应用生命周期

### 窗口与快捷入口

- 提供主窗口及 macOS 顶部菜单栏入口。
- 关闭主窗口后应用继续在菜单栏运行，服务继续运行。
- 点击菜单栏入口或按快捷键可快速显示主窗口。
- 快捷键可配置，默认同时按住 `Option（Alt）+S+L`，不是顺序按键。

### 自动启动

- 支持应用开机自动启动选项，在 macOS 中指用户登录后启动应用。
- 每个服务有独立的「随管理器启动」选项。
- 应用启动时检查标记服务，识别仍运行实例，跳过重复启动并启动未运行实例。
- 单个失败不阻塞其他服务，显示原因，不反复自动重试。
- 手动、登录后和 MCP 自动启动管理器，均执行相同服务自动启动检查。

### 退出与恢复

有运行服务时，真正退出应用提供三个选项：

1. 停止全部并退出：停止本应用管理的全部运行服务，停止失败时展示结果并处理，不能声称已全部停止。
2. 保留服务并退出：管理器退出，服务继续运行。
3. 取消：保持应用运行。

- 「全部」不包括仅登记的数据库、Redis、Docker 容器或其他外部进程。
- 再次打开时重新识别保留运行的服务，避免重复启动。
- 重新连接后的日志从可获取的新输出开始展示，不补历史日志。

## 5. 日志

- 实时查看标准输出和错误输出。
- 内存保留有限近期输出，超限丢弃，退出后清空，不保存历史日志文件。
- MCP 可读取当前仍在内存中的日志。
- 服务自身写入的日志文件由服务管理，管理器不修改或清理。
- 内存上限在实现时确定，不扩展为历史日志存储。

## 6. 资源登记与绑定

### 通用规则

- 登记已有运行时、工具及项目连接资源，支持 MySQL、Redis、PHP、Node.js 及其他类型的资源，支持记录不同版本。
- 资源可复用、共享，按「项目 + 环境」绑定；同一环境可绑定多个同类资源，同一资源可绑定多个项目 / 环境。
- 支持登记、修改、移除资源及绑定、解绑，界面与 MCP 均可操作。
- 删除登记或解绑只改变记录，不删除数据库、数据目录、安装文件、容器或镜像。
- 不下载安装、升级或卸载资源，不改变整机默认运行时版本。
- 绑定说明使用范围和用途，不替代数据库账号权限，不自动执行资源依赖启停。

### 登记信息

- 通用字段：稳定 ID、名称、类型、版本（适用时）、来源、用途、说明。
- 连接资源：地址、端口、账号（适用时）、密码等凭据、数据库名或数据库索引 / 命名空间等类型相关信息。
- 本机运行时和工具：版本、准确可执行文件路径。
- 绑定信息：项目、环境、资源及在该范围的用途，MCP 可查询完整关系。
- 例如 Peanut Admin / 开发环境绑定两个允许用于开发的数据库，供 AI 准确选择。

### MySQL、Redis 等连接资源

- 数据库增加「测试连接」，返回成功或具体错误，只检查已登记目标，不静默切换。
- 测试连接不执行建库、数据修改、迁移或清理。
- Redis 纳入首版资源登记、项目环境绑定及凭据读取；专用数据浏览和命令控制台不在范围内。
- 资源自身进程不会仅因登记或绑定而被管理器启停。

### PHP、Node.js 及其他版本

- 登记本机已有的多个版本，服务启动时选择已绑定到其项目环境的适用版本及工具路径。
- 路径不存在或版本不可用时报告原因，不静默改用其他版本。
- 不安装版本管理器，不改变终端或整机默认版本。
- 其他服务、运行时及工具按适用字段登记；登记类型不等于为每种产品提供专用进程控制或数据管理。

### 凭据

- 密码等秘密使用 macOS 钥匙串存储，普通配置保存凭据引用。
- 普通界面列表及 MCP 资源列表隐藏秘密，不写入普通日志。
- 独立 MCP 工具允许读取已绑定资源的密码等凭据，供 AI 开发使用。
- 查询和凭据读取要求明确项目、环境和资源，并核对绑定；不能以某项目环境名义读取未绑定资源。
- 私有资源配置、凭据、用户日志及生成产物不进入公开 Git 仓库。

### Docker

- 首版只登记已有容器并检查状态，登记明确的容器身份、Docker context 及所需连接信息。
- Docker 内数据库等资源填写本机实际可访问的映射地址和端口。
- 区分容器运行状态与 Docker 不可连接、目标不存在、检查失败，不把未知状态显示为正常。
- 不提供容器启动、停止、重启和日志，不创建容器、不下载镜像，不管理卷或数据删除。
- 普通服务的启停能力不自动扩展到登记的容器。

应用用户的私人资源登记与本仓库 [项目运行资源登记](resource-registry.md) 用途不同：后者仅登记开发本项目实际使用的资源，不填入用户私人连接信息。

## 7. 本地 MCP

- 随应用提供本地 STDIO 接入程序，无需用户为此额外安装 Node.js 或 Python。
- 提供 Codex 等 AI 客户端接入说明、命令或对应配置。
- 覆盖界面全部业务及设置能力，包括项目、环境、分组、服务、资源、绑定、运行操作、近期日志、状态、测试连接和应用设置。
- 界面和 MCP 共用配置与运行状态，不另起镜像配置或重复服务实例。
- 管理器未运行时允许 MCP 自动启动管理器，并执行服务自动启动检查。
- 工具操作明确显示稳定 ID 和目标层级，同名歧义返回候选。
- 普通列表不返回密码，独立工具按已绑定项目环境读取凭据。
- 系统授权仍走 macOS 流程；停止超时等保留的用户决定不能由 MCP 绕过。

## 8. 安装与发布

- 提供便捷的 macOS 安装方式。
- `dev` 为日常集成及默认分支，本地主目录检出 `dev`。
- `main` 为稳定分支，推送时自动生成预览版。
- 推送版本 tag 时自动生成正式版。
- 本次文档确认不授权推送 `main`、打 tag 或实际发布，不实现发布工作流。
